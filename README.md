# meshinowa（メシノワ）

おいしい店は、友達が知っている。

友達のおすすめを地図から探すiPhoneアプリ。iOS 17以上、SwiftUI、Google Maps / Places、Cloudflare Workers / D1 / R2を使用します。

## 起動

1. `meshinowa.xcodeproj`をXcodeで開き、`meshinowa`スキームでiPhoneシミュレータを選択してRun。
2. Googleの設定は[Google Maps / Places](docs/GOOGLE_PLACES.md)、サーバーの設定は[Cloudflare](cloudflare/README.md)を参照。
3. 実機では自分のTeamで署名してください。構成変更後は`xcodegen generate`でプロジェクトも更新します。

## 実装した機能

- 地図：店名・ジャンル・表示範囲で検索、ピンと店舗カルーセル、一覧、写真と提供元クレジット、店舗詳細、Google Mapsへの経路案内。
- 現在地：ボタンを押した時だけ使用中権限を要求し、単発で取得。位置を永続保存せず、バックグラウンドでは取得しません。
- 保存：独立した「いいね」と「行った」。行った＝レビューがある店舗で、レビュー削除後は行ったから外れます。いいねはそのままです。
- 保存一覧：検索、保存順・店名順・自分の評価順・友達の評価順・距離順、未レビュー絞り込み、地図表示。未評価・距離不明は並び替えの末尾です。
- レビュー：1〜5点の0.5刻み、ひとこと300文字、おすすめ料理100文字、また行きたい、来店日、写真5枚まで。写真はメタデータを除去したJPEGとして記録します。
- プロフィール：表示名・自己紹介160文字・8種類のアイコンを編集、ID共有、件数・最近のレビュー・レビュー一覧・マイマップ。
- 友達：ID検索、申請・承認・拒否・取り消し、解除、お気に入り、友達プロフィール、ブロック・解除、フィードとおすすめマップ。
- Friend Lens：全員・お気に入り・選択した友達。地図・カード・実店舗詳細が同じ条件で集計します。
- 公開設定：ID検索への表示と、友達の平均評価・フィードへの掲載を切り替えます。
- 共有：レビュー変更と削除を端末のJSONへ一緒に記録し、送信成功まで保持。通信失敗・再起動を跨いで再試行し、古い送信結果で新しい編集を消しません。
- バックアップ：設定から保存・レビュー・写真・来店日を自分専用に保存・復元。バージョン競合時は上書きを止めます。常時自動同期ではありません。
- 引き継ぎ：元の端末でバックアップして引き継ぎコードを発行し、新端末でコードを入力。プロフィール・友達関係と記録を引き継ぎます。コード再発行で古いコードは無効になります。
- アカウント削除：確認後にサーバーのアカウント・関連データと端末の記録を削除します。R2の残存データはアクセスを即時に失効し、定期処理で掃除します。

## データの扱い

Cloudflare未設定では端末内モードで、友達タブは架空データのデモです。プロフィールも端末内で編集できます。
接続時はゲストを作成し、認証情報をこの端末だけのKeychainに保存します。保存失敗を無視したり、本番サーバーの認証切れで別アカウントを自動作成したりしません。localhostの開発用DBが空、または以前と異なるDBになったと確認できる場合だけゲスト接続を復旧し、端末のレビューを再共有します。
評価・ひとこと・おすすめ料理・また行きたいをサーバーへ送ります。写真と来店日は通常の友達共有では送らず、明示したバックアップだけが対象です。
引き継ぎコードはアカウントの鍵なので、安全に保管してください。バックアップなしでは端末の写真・保存情報は引き継げません。

新しいGoogle店舗はPlace IDで照合します。旧JSONも読み込み、Place IDがない記録は店名と丸めた座標で照合します。
Googleの店舗写真や写真参照名は独自に永続保存せず、端末内メモリだけで一時的に共有します。

## 検証

XcodeでProduct → Test、または次のコマンドを使います。UIテストは外部サーバーへ接続せず、プロフィール編集・設定・再起動後の保持を確認します。

```sh
xcodebuild test -project meshinowa.xcodeproj -scheme meshinowa -destination 'platform=iOS Simulator,name=iPhone 17'
npm run check --prefix cloudflare
npm test --prefix cloudflare
```

テストは一時ファイルと架空データを使用します。バックエンドのテストは本番サービスへ接続しません。
[ハッカソンでの確認手順と残る環境作業](docs/HACKATHON_CHECKLIST.md)を参照してください。
