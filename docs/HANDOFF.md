## デザインの決まり

デザインの元は `output/wa-design/` の HTML です（ブラウザで開くと動きも見られます）。

| ファイル | 内容 |
|---|---|
| `category-pins.html` | ジャンル別ピンの形・状態（採用） |
| `tabbar-noren.html` | タブバー（案2「提灯の灯り」を採用） |
| `screens.html` | 保存・友達・プロフィール |
| `review-editor.html` | 評価の画面 |
| `index.html` / `tabbar.html` | 初期の検討（不採用を含む） |

1. **見た目はモダン、和は「選んだ瞬間」だけ。** 例：カテゴリののれん、タブを押すと灯る提灯、記録すると押される判子。ふだんの画面に和柄や和のモチーフを足さない。
2. **形＝ジャンル、色＝自分の記録。** ピンと一覧の器の形はジャンル（`FoodGenre`）。色は、白に緑の線＝記録なし、ピンク＝いいね、緑＝レビュー済み／友達の評価、からし色＝自分の評価（自分の評価にだけ使う）。
3. **のれん（`NorenTabs`）の部品と動きは変えない。** 項目は `RestaurantGenre` に足せば並ぶ。
4. **タブバーは文字なしのアイコンだけ。** 真ん中の評価ボタンはバーより少し大きく、上下に少しはみ出す。

## ジャンルの判定（`FoodGenre.infer`）

1. Google Places の種類（`placeTypes`）
2. 店名の言葉（先にある組ほど優先。「バーガー」は「バー」より先に洋食として見る）
3. 地図のカテゴリ（カフェ・パン・醸造所）
4. どれでも分からなければ「その他」。ただし、ジャンルを指定して検索したお店は `searchedFoodGenre` でそのジャンルとして扱う。

Google の種類名には、実在を確かめていないもの（例：`yakiniku_restaurant`、`japanese_izakaya_restaurant`）も含めています。実在しなくても一致しないだけで害はありません。

## 評価の流れ

真ん中のボタン → `ReviewTargetPicker`（店名検索・マップで選んでいるお店・いいねして未評価・評価を変える） → `QuickRatingSheet` → 必要なら `ReviewEditor`。
保存は `LocalReviewStore.save`、送信は `MeshinowaApp` の `reviews.onSaved` → `FriendStore.upload`（Cloudflare）。この流れは変えていません。
