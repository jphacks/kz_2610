# 招待・共通の行きたい・共有カード

2026-11-03のユーザー確認済みの選別に沿った初期版。
添付ZIPの原案は `output/wa-design/friend-sharing-source-spec-20261103.md`。
原案内の「決定」「採用」より、この選別を優先する。

## 採用した範囲

- 共有カード：店舗詳細の既存の共有ボタンから開く。4:5（1080×1350）の1種類。名前は初期オフ。自分の評価・ひとことは表示を選べる。写真は自分のレビューの最初の1枚だけを任意で使用。写真なしは器。友達の情報・Googleの店舗写真は受け取らない。プレビューからiOSの共有シートへ渡す。
- 招待：リンクの送信・コピー、標準QR、標準カメラの読み取り、相手の確認、申請・承認、未インストール時のWeb案内。既存のID検索も維持。再発行すると以前のリンクは無効。自動の7日期限は設けない。
- 共通の行きたい：友達プロフィールから、1人の友達との一覧へ進む。店舗詳細と「誘う」の共有リンク。自分と相手がともに共有オンのときだけサーバーが共通部分を返す。初期オフ。設定は友達全員との共有を一括オン／オフ。いいねは対象外。
- 例外：招待の無効・自分・友達・申請済み・届いた申請・通信失敗、共通一覧の自分オフ・相手オフ・0件・関係解除・通信失敗を区別する。

## 今回入れないもの

- 装飾QR、アプリ内QR読み取り、招待のインストール後の自動引き継ぎ。
- 共通の行きたい専用の地図、保存画面からの追加入口、事前の共通件数取得。
- カードの9:16切り替え、おすすめ料理の独立設定、専用の写真保存ボタン、複数の作成入口。
- 新規タブ、グループ、チャット、日程調整、予約。

## データとAPI

- migration `0006_friend_invites.sql`：プロフィールごとの招待。ID検索オフでも、現在有効な招待からだけ申請を許可する。ブロック・既存の友達・逆方向の申請のガードを維持。
- migration `0007_common_want_to_go.sql`：共有同意を追加。既存クライアントの公開設定保存では、この同意を変更しない。
- `POST /v1/invites` `{rotate:false}`：現在の招待を取得（なければ作成）。`rotate:true` で再発行。GETではデータを作らない。
- `GET /v1/invites/:token`：認証済みの受け取り状態を確認。`POST /v1/invites/:token/request`：確認済みの招待から申請。既存の承認APIを再利用。
- `GET /i/:token`：表示名だけを出す公開案内。ID・handle・レビューは出さない。no-store、noindex、no-referrer。ユーザー入力はHTMLエスケープ。
- `PUT /v1/preferences/want-to-go` `{share_want_to_go:bool}`：共有の同意だけを更新。
- `GET /v1/want-to-go/common?friend_id=...`：現在の関係・ブロック・両者の同意を確認。共通部分以外をクライアントへ渡さない。ページごとに再確認。
- 共通一覧は表示中の60秒更新と手動更新で変更を反映。バックグラウンド移行では一覧を消す。オフ・解除後の未更新画面や、外部共有済みの画像・文面を遠隔削除することはできない。
- 店舗の照合ではGoogle切り替え前の店名＋座標も考慮。アプリでの重複除去は `SavedRestaurant.isSameStore(as:)`。

## 公開前に必要な設定

ユーザー確認：Cloudflareの公開URL・独自ドメインはまだ未用意。
この変更では公開リソース作成、デプロイ、push、mainへの取り込みを行わない。

1. Cloudflareの公開先を用意し、既存のD1/R2/認証設定を行う。migrationを0007まで適用する。
2. `Config/Cloudflare.xcconfig.local` に公開先を設定する。実機用にlocalhostを使わない。
3. Appleのアプリ識別子（Team IDを含む `TEAMID.jp.meshinowa.app`）をWorkerの `APPLE_APP_ID` に設定する。AASAはこれが有効なときだけ配信する。
4. `Config/Meshinowa.entitlements` の空配列へ、実際のホストの `applinks:ホスト名` を追加する。署名チーム側でもAssociated Domainsを有効にする。架空のホストは入れない。
5. App Store公開後、実際のストアURLをWorkerの `APP_STORE_URL` に設定する。未設定では架空のストアボタンを出さず、公開準備中と案内する。
6. Universal Linksは同じドメイン内のSafari遷移ではWebに残る場合があるため、Webの明示的な「アプリで開く」は登録済みの `meshinowa://invite/:token` を使う。受け取ったトークンは必ずサーバーで確認し、開いただけでは申請しない。
7. 実機2台で、招待・申請・承認・再発行・ブロック・両者の共有オン／オフを確認する。標準カメラでQRを読み取る。未インストール端末でも案内を確認する。
