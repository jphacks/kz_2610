# 作業指示：地図の見やすさ（A＋B＋D）

作成：2026-10-29（ユーザー依頼。見た目のモック：`output/wa-design/map-readability.html` の右端「A＋B＋D」）

## なぜやるか

仕上げで入れた地図の配色（`MeshinowaMapStyle`）が消しすぎていて、駅名・目印の名前が出ず、近くのお店の名前も出ない。今どこを見ているのか分かりにくい、とユーザーから指摘があった。

## 進め方

- `codex/ui-polish` から `codex/map-readability` を切って作業する。
- A・B・D を **それぞれ1コミット**（必要なら細かく分けてよい。1コミット1目的）。コミット者は Yuppy07、AI の署名は付けない。
- お店の検索・保存・通信の仕組みは変えない（D の地名の取得だけ新しく足す）。
- 各段階で単体テスト（`-only-testing:meshinowaTests`）を通し、最後に UI テストも含めて全部流す。
- シミュレータ（Google のキーあり）で、東京駅周辺を引き・寄りの2段階で見て確かめ、`docs/HANDOFF.md` に結果を追記する。
- push と `main` への取り込みはユーザーの承認を取ってから。

## A：配色を「消しすぎない」形に直す

場所：`meshinowa/DesignSystem/MeshinowaTheme.swift` の `MeshinowaMapStyle.json`。

**出すもの**
- 駅名と駅のマーク（`transit.station` の labels.icon / labels.text）
- 目印の名前：観光地・公共施設・公園・学校・医療・礼拝所（`poi.attraction` `poi.government` `poi.park` `poi.school` `poi.medical` `poi.place_of_worship` の labels.text）。アイコンは消したままでよい
- 地名・町名（`administrative` の labels）

**消すもの**
- お店（`poi.business` 全体。アプリのピンと重ならないように）
- 高速道路の番号・IC・JCT（`road.highway` の labels。`road.highway.controlled_access` も）
- 目印のアイコン（`poi` の labels.icon）

**色**

| 対象 | 今 | 直した後 |
|---|---|---|
| 陸地 | `#F6F1E6` | `#F1EADB`（少し濃くして道を浮かせる） |
| 街区（`landscape.man_made`） | `#EFE8D8` | `#EAE2D0` |
| 道路の面 | `#FFFFFF` | `#FFFFFF`（そのまま） |
| 道路の縁（geometry.stroke） | `#E6DDCB` | `#DCD2BE` |
| 大通り・高速の面 | `#FBF6EC` | `#FFFFFF`（ほかの道路と同じ白） |
| 駅名の文字 | — | `#3B5F86`（縁取り `#FDF8EE`）。ほかの地名より少し目立たせる |
| 地名・目印の文字 | `#7B7F7C` | `#6B716D`（`secondaryText`、縁取り `#FDF8EE`） |
| 水・緑・線路 | — | 今のまま |

完了の条件：東京駅周辺で「東京」「大手町」「日本橋」などの駅名と、「丸の内」「八重洲」などの町名が読める。JCT・IC・道路番号は出ない。Google のお店のアイコン・名前は出ない。

## B：アプリのピンの下に店名を出す

場所：`meshinowa/Views/GoogleMapCanvas.swift`（`GoogleMapPin` とマーカーの画像を作るところ）、`meshinowa/DesignSystem/RatingStamp.swift` の `PlacePin`、`meshinowa/Views/MapHomeView.swift`（`shownResults` の間引き）。

- **出す条件**：ある程度拡大したときだけ。目安は表示範囲の幅が約1.5km以下（ズームでいうと 15.5 前後。実機で見て決めてよい）。引いたときは今どおりピンだけ。
- **見た目**：ピンの下に1行。墨色（`ink`）の文字に白い縁取り（背景の板は付けない）。11pt 程度、選択中のピンは少し大きく太く。10文字前後を超えたら「…」で切る。
- **重なり**：今のピンの間引き（画面上で30pt以内は優先度の低い方を隠す、最大60件）に、名前の幅も入れて判定する。名前同士が重なるときは、優先度の低い方の名前だけを隠す（ピンは残す）。優先度は今と同じ：選択中 → 友達の評価 → 自分の記録 → 一般。
- **性能**：マーカーの画像は今も `signature` が変わったときだけ作り直している。名前の表示・非表示も `signature` に含め、ズームのたびに全部作り直さないようにする（名前を出すかどうかが切り替わったときだけ）。
- 友達のおすすめマップ・保存の地図にも同じ表示が出てよい（`GoogleMapCanvas` を共有しているため）。出したくない画面があれば引数で切れるようにする。
- VoiceOver：マーカーの `title` は今どおり店名。

完了の条件：寄ったときに店名が読め、引いたときは名前が消える。名前どうし・名前とピンが重なって読めない状態にならない。地図の動きがカクつかない。

## D：今見ている地域名を検索欄に出す

場所：`meshinowa/Views/MapHomeView.swift` の `searchField`。地名の取得は新しい小さな型（例：`MapAreaNamer`）に分ける。

- **見た目**：検索欄の入力の文字の上に、小さな1行で「地域名＋周辺」だけを出す（例：「丸の内周辺」）。**ピンなどのアイコン・絵文字は付けない**（2026-10-29 ユーザー指定。モックの📍は無視する）。11pt・緑（`green`）・太字。検索欄の高さは変えない（入力欄の文字を少し上に詰める）。入力中（フォーカス中）は隠してよい。
- **地域名の取り方**
  - 地図が止まったとき（`onCameraEnd`）に、地図の中心で1回だけ逆ジオコーディングする。
  - 料金がかからない Apple の `CLGeocoder`（日本語）を使う。地図の表示は Google のまま。
  - 使う名前の順：町名（`subLocality`、例：丸の内）→ 市区町村（`locality`、例：千代田区）→ 都道府県。
  - 前回の地点から 300m 以内しか動いていなければ取り直さない。前の問い合わせが終わる前に地図が動いたら、古い結果は使わない。
  - 取れなかったときは前の名前のままにし、最初から取れていなければ行ごと出さない。
- **現在地ボタン**を押して移動した直後は「現在地の周辺」と出す（地図を動かしたら地域名に戻る）。
- 現在地の青い点は今も出る設定（`isMyLocationEnabled = true`）。変えない。
- テスト：地域名の選び方（町名→市区町村→都道府県）、300m 以内では取り直さないこと、古い結果を捨てることを単体テストで確かめる（`CLGeocoder` は差し替えられるようにする）。

完了の条件：地図を動かして止めると、検索欄の上の地域名が変わる。動かしている最中に何度も問い合わせない。
