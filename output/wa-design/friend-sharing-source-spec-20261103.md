# 友達招待・一緒に行きたいお店・共有カード 仕様

対象：meshinowa（SwiftUI / iOS 17+）。見本は `招待・行きたい・共有カード.dc.html`（操作できるプロトタイプ）と `共有カード見本.dc.html`。
見本の人物・お店・感想・URLはすべて架空。通信はすべて模擬。

デザインの決まりは `output/wa-design/ui-handoff-20261029.md` と同じ（画面の地 `ground` #FDF8EE、カード・入力は白＋1pt `hairline`、緑＝主操作・友達・行きたい、からし色＝自分の評価、ピンク＝いいね）。見本のアイコンは Material Symbols の代用。実装では SF Symbols を使う。

---

## 1. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| QRの読み取り | iOS標準カメラで読む。アプリ内に読み取り画面は作らない | カメラ権限・読み取りUIが不要。招待シートに「iPhoneのカメラで読み取ると…」と案内するだけで足りる |
| 招待リンク | 自分専用のトークン付きURL。**7日で期限切れ**。作り直しは「新しいリンク」ボタンで手動のみ。作り直すと古いリンクは無効 | IDをURLに入れないので、期限切れ・作り直しで止められる |
| Webページに出す情報 | 表示名とアイコンだけ | 申請前にIDや評価を公開しない |
| 行きたいの共有範囲 | **スイッチ1つ（友達全員にオン／オフ）。初期はオフ** | 見えるのは共通のお店だけなので、友達ごとの設定までは不要。設定を1か所に保てる |
| 相手に見えるもの | 2人ともオンのとき、**共通のお店だけ**。相手の「行きたい」一覧全体、「いいね」は見えない | 共有の不安を小さくする |
| 共有をオンにするきっかけ | 共通の画面を初めて開いたときだけ説明を出す。設定画面にも同じスイッチ | 友達ができた瞬間には聞かない |
| 共有カードの形 | LINEなど用 4:5（360×450pt → 1080×1350px）と、ストーリーズ用 9:16（360×640pt → 1080×1920px）を切り替え | 同じ内容から作れ、操作は切り替え1つ |
| カードの初期項目 | 自分の名前・自分の評価・ひとことがオン。おすすめ料理・自分の写真はオフ | |
| カードの写真 | **本人がレビューに付けた写真だけ**。なければ写真なし（ジャンルの器）。Googleの店舗写真は使わない | 写真の権利。出典は「写真：（名前）」を写真の右下に表示 |
| カードに添えるリンク | 共有文に、店名と地図アプリで開けるリンク。画像にはリンクもQRも載せない | 画像だけでおすすめが伝わり、場所は共有文で開ける |

## 3. 全体の流れ

1. はるかが「友達を招待する」→ 招待リンクをLINEで送る（または会ってQRを見せる）
2. ゆいがリンクを開く → アプリありなら確認画面、なしならWebページ → インストール後にもう一度リンクを開く
3. ゆいが「友達申請を送る」→ はるかが承認 → 友達になる（既存の承認後の案内）
4. どちらかが友達のプロフィールで「一緒に行きたいお店」→ 初回の説明 → 共有をオン
5. 2人ともオンなら共通のお店が並ぶ → 「誘う」で店名と地図リンクを送る
6. 行ったあと、店舗詳細から「カードにして共有」→ LINEやストーリーズへ

## 4. 画面と動作

### ① 招待

**友達を追加シート（invite）**
- 自分のアイコン・表示名・@ID
- QRコード（184pt角。招待URLから端末で生成。デザインは下の「招待QRコード（採用案1b）」）
- 「iPhoneのカメラで読み取ると あなたへの申請画面が開きます」
- 有効期限の札（mint地）「11月10日まで有効（あと7日）」
- 主ボタン「招待リンクを送る」→ `ShareLink`（共有文は下記）
- 「リンクをコピー」→ クリップボードにURL、トースト「リンクをコピーしました」
- 「新しいリンク」→ 確認「新しいリンクを作りますか？／今のリンクとQRコードは使えなくなります。」［キャンセル］［作る］→ トースト「新しいリンクを作りました」
- 「IDで探す」：既存のID完全一致検索と状態ラベル（自分・友達・申請あり・申請中）をそのまま
- 注記「リンクを開いただけでは友達になりません。相手が申請し、あなたが承認するとつながります。」

**招待QRコード（採用案1b「緑のつぶ」）** 見本：`招待QR デザイン.dc.html` の 1b

| 項目 | 値 |
|---|---|
| 生成 | `CIFilter.qrCodeGenerator`、`correctionLevel = "H"`、入力は招待URL（UTF-8）。行列（ブール値の2次元配列）を取り出して SwiftUI の `Canvas` で描く。画像を拡大して使わない |
| 余白 | 周りに点4つ分の白（クワイエットゾーン）。白＋1pt `hairline`・角丸18のカードの中に置く |
| 大きさ | 画面で 184pt 角（余白込み）。最小 176pt |
| 地 | 白 #FFFFFF。クリーム地・反転は使わない |
| 点 | 直径 0.86点分の円（半径 0.43）、色 `mintInk` #1F6B4F。点どうしはつなげない |
| 角の目（3か所） | 外枠：7点角の範囲に線幅1点・6点角・角丸2.4点の正方形、色 #1F6B4F。瞳：3点角・角丸1.2点、同色。目の範囲（7×7）には円の点を描かない |
| ロゴ | 中央。全体の幅の22%（奇数の点数に丸める）の範囲の点を描かない。白い円（その範囲の直径）→ `mint` #DDF0E4 の円（半径を0.6点小さく）→ `BowlMark`（ロゴ範囲の74%、輪 `green`、穴 `mint`、箸 `accent`）|
| 使わない | からし色・ピンク・グラデーション・影 |
| 期限切れ | QRは描かず、同じ大きさの `field` #F4F5F2 の面にアイコンと「期限が切れました」 |
| 読み取り確認 | iPhone標準カメラ・LINEのQRリーダーで、画面の明るさ50%・30cmで読めること。点の色を変えるときは白とのコントラスト 4.5:1 以上 |
| VoiceOver | 「招待QRコード。iPhoneのカメラで読み取ると申請画面が開きます」 |

```swift
Canvas { ctx, size in
    let n = matrix.count, u = size.width / CGFloat(n + 8)   // 余白4点ずつ
    for y in 0..<n { for x in 0..<n where matrix[y][x] && !isEye(x, y, n) && !isLogo(x, y, n) {
        let r = u * 0.43
        let c = CGPoint(x: (CGFloat(x) + 4.5) * u, y: (CGFloat(y) + 4.5) * u)
        ctx.fill(Path(ellipseIn: CGRect(x: c.x - r, y: c.y - r, width: r * 2, height: r * 2)),
                 with: .color(MeshinowaTheme.mintInk))
    } }
    // 角の目・ロゴは別に描く
}
```

**期限切れ（inviteExpired）**：QRの場所に「期限が切れました」、説明「このリンクとQRコードは使えません。新しいリンクを作ってから送ってください。」、主ボタン「新しいリンクを作る」（確認なしで作る）。送信・コピーは出さない。

**招待を受け取る（Universal Link でアプリが開く）**

| 状態 | 表示 | ボタン |
|---|---|---|
| 確認中 | 「招待を確認しています…」 | － |
| 確認 | アイコン・表示名・@ID、「ゆいさんから招待が届いています」、説明「申請すると、ゆいさんが承認したときに友達になります。友達になると、お互いの評価が地図に表示されます。」 | 「友達申請を送る」／「今はしない」 |
| 申請中 | 「申請中」の札、「ゆいさんが承認すると友達になります。申請は「友達」タブで取り消せます。」 | 「閉じる」 |
| 申請が届いている | 「ゆいさんから友達申請が届いています」 | 「承認する」／「見送る」 |
| 友達になった | 「ゆいさんと友達になりました」 | 「ゆいさんの評価を地図で見る」（既存の案内）／「閉じる」 |
| すでに友達 | 「ゆいさんとはすでに友達です」 | 「プロフィールを見る」／「閉じる」 |
| 自分の招待 | 「これはあなたの招待です」「友達に送ると、相手がこの画面から申請できます。」 | 「招待を送る」／「閉じる」 |
| 無効 | 「この招待は使えません」「期限が切れたか、新しいリンクに変わっています。送ってくれた人に、もう一度送ってもらってください。」 | 「閉じる」 |
| 通信失敗 | 「招待を確認できませんでした」「通信状態を確認して、もう一度お試しください。」 | 「もう一度試す」／「閉じる」 |

- 無効には、期限切れ・作り直し済み・ブロック関係・退会済みをまとめる（理由を推測させない）。
- 未接続（Cloudflare未設定）のときは既存の「友達の機能につながっていません」を出す。
- 申請は確認画面で返ってきた相手の `id` で送る（handle を再検索しない。既存と同じ）。

**未インストール時のWebページ**
- ロゴ、相手のアイコンと「ゆいさんから メシノワへの招待です」
- 「友達の「おいしかった」が、あなたの地図に。友達が評価したお店を地図で探せるiPhoneアプリです。」
- 「App Storeで入手」
- 「入れたあとは」1. このページに戻るか、もう一度リンクを開く　2.「アプリで開く」を押して、ゆいさんに申請する
- 「アプリで開く」（Universal Link を再度開く）
- インストール後の自動引き継ぎはしない。
- 無効なトークンのときは相手情報を出さず「この招待は使えません」とアプリの説明だけ。

### ② 一緒に行きたいお店

**友達を選ぶ（保存の「友達と共通」から）**：見出し「誰と一緒に行く？」、説明「選んだ友達と、2人とも「行きたい」に入れているお店を表示します。」。各行に名前と「行きたいを共有中／行きたいを共有していません」。共有していない友達も選べる。

**友達のプロフィール**：「一緒に行きたいお店」の行。サブ文は、共有オンで件数があるとき「2人とも行きたいお店 3軒」、それ以外は「2人とも「行きたい」に入れたお店」。

**開いたときの分かれ方**

```
自分の共有がオフ ─ 初回 → 初回の説明
                └ 2回目以降 → 共有がオフです
自分がオン → 読み込み → 相手がオフ → 相手が共有していない
                     → 0件 → 共通のお店はまだありません
                     → 1件以上 → 一覧
                     → 失敗 → 読み込めませんでした
```

**初回の説明**
- 見出し「2人とも行きたいお店を見つけよう」
- 「あなたと友達の両方が「行きたい」に入れたお店だけを表示します。」
- 「友達に見えるのも共通のお店だけです。「行きたい」の一覧全体は見えません。」
- 「「いいね」は共有されません。」
- 「設定からいつでもオフにできます。」
- 「行きたいを共有する」→ オンにして読み込み／「今はしない」→ 共有がオフです

**一覧**
- 見出し「ゆいさんと一緒に」＋「2人とも行きたいお店 3軒」、自分と相手のアイコンを重ねて表示
- 一覧／地図の切り替え
- 行：サムネ（写真なしは白＋細線＋器）、店名、ジャンル・エリア、「2人とも行きたい」（旗）、右に「誘う」
- 行を押す → 店舗詳細。「誘う」→ 共有シート（店名と地図リンク）
- 注記「この一覧は、あなたとゆいさんにだけ表示されます。」
- 並び順：2人のうち遅いほうの追加日時の新しい順

**地図**：既存の友達だけの地図（`FriendMapScreen`）と同じ作りで、共通のお店だけを旗のピンで表示。下のカードに「ここに行こうと誘う」。

**空・状態の文言**

| 状態 | 見出し | 本文 | ボタン |
|---|---|---|---|
| 0件 | ゆいさんと共通のお店はまだありません | お店の旗を押して「行きたい」に入れると、ゆいさんも入れていた場合にここに表示されます。 | 地図でお店を探す／閉じる |
| 相手がオフ | けんたさんは「行きたい」を共有していません | けんたさんが共有をオンにすると、共通のお店が表示されます。 | 閉じる（催促のボタンは置かない） |
| 自分がオフ | 「行きたい」の共有がオフです | オンにすると、共有している友達との共通のお店が見られます。相手に見えるのも共通のお店だけです。 | 共有をオンにする／閉じる |
| 失敗 | 読み込めませんでした | 通信状態を確認して、もう一度お試しください。 | もう一度読み込む／閉じる |

**設定**：「共有」の項に「行きたいを友達と共有」スイッチ。下に「オンにすると、同じくオンにしている友達との共通のお店だけが、お互いに表示されます。「行きたい」の一覧全体や「いいね」は見えません。解除やブロックをした相手には表示されません。」

- 相手がオンかオフかは、友達本人にだけ分かる（友達を選ぶシートの状態表示）。
- 解除・ブロック後は共通の一覧からも外れる（サーバー側で友達関係を確認）。
- 行きたいはレビューを書くと外れる（既存のトリガー）。共通の一覧からも自然に消える。

### ③ 共有カード

**共有方法を選ぶ**（店舗詳細の共有ボタン）：見出し「（店名） を共有」、「カードにして共有」／「店名と地図のリンクを送る」（今の「店名と住所を共有」を置き換え）／「キャンセル」。

**カードの作成**
- 形の切り替え「LINEなど 4:5」「ストーリーズ 9:16」
- プレビュー（実寸の縮小）
- 載せる項目のスイッチ：自分の名前（はるか）／自分の評価（4.5）／ひとこと／おすすめ料理／自分の写真（1枚）
  - 評価・ひとこと・おすすめ料理・写真は、自分のレビューにあるときだけ行を出す
- 注記「友達の名前・評価・コメントはカードに載りません。」
- 「画像を保存」→ 写真へ保存（追加のみの写真権限）、トースト「写真に保存しました」
- 「共有する」→ `ShareLink` に画像（PNG）＋共有文

**カードの中身（見本：`共有カード見本.dc.html`）**

| 要素 | LINE 4:5 | ストーリーズ 9:16 |
|---|---|---|
| 地 | `ground` #FDF8EE、内側 16pt | 同、上 64pt・下 92pt は文字を置かない（ストーリーズの操作部品と重なるため） |
| 見出し | なし | 「はるかのおすすめ」（名前オフで「おすすめのお店」）＋ロゴ |
| 写真枠 | 角丸 14。自分の写真 or `photo` 地＋器。左上にジャンル札（1bと同じ）。写真ありは右下に「写真：はるか」（名前オフで「写真：投稿者」） | 角丸 18、高さを大きく |
| 店名 | Zen Maru Bold 22pt（15文字超は 19pt）、2行で省略 | 26pt（22pt）|
| ジャンル・エリア | 12pt、ピン印 | 13pt |
| 判子 | 自分の評価。58pt・枠3pt `accent`・-6°・点数 M PLUS 21pt＋下に名前（名前オフで「評価」） | 64pt |
| ひとこと | 白＋細線の面、ラベル「はるかのひとこと」（名前オフで「ひとこと」）、14pt・3行で省略（料理ありは2行） | 15pt・5行 |
| おすすめ料理 | 「おすすめ：鯛の土鍋ごはん」12pt | 13pt |
| フッター | ロゴ＋「メシノワ」＋「友達のおすすめを地図で」 | 同 |

- 写真なし・ひとことなしのときは写真枠を大きくして余白を埋める。
- エリアは住所から町名まで（番地は載せない）。
- SwiftUI の `ImageRenderer` で 3倍に書き出す。

**共有文**

```
ここ今度行かない？
ごはん処 こもれび
（地図のリンク）
```

- 地図のリンクは、店舗の名前と座標から Apple マップのURLを作る。Google の place_id がある場合は Google マップのURLでもよい（どちらにするかは実装時に決める）。
- 一緒に行きたいお店の「誘う」も同じ共有文（画像なし）。
- 招待の共有文：`メシノワで友達になろう！` ＋改行＋招待URL。

## 6. 必要なデータ・API（Cloudflare）

### 招待

```sql
create table invites (
  token text primary key,          -- 推測できない乱数（128bit以上、URLセーフ）
  user_id text not null references profiles(id) on delete cascade,
  created_at text not null default (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  expires_at text not null,        -- 作成から7日
  revoked_at text
);
```

| API | 内容 |
|---|---|
| `GET /v1/invites/current` | 有効な自分の招待（なければ作る）。`{token, url, expires_at}` |
| `POST /v1/invites` | 新しく作る。古いものに `revoked_at` |
| `GET /v1/invites/:token` | 受け取り側。`{state, profile?: {id, display_name, avatar_symbol, handle}}`。state は `ok / self / friend / pending_sent / pending_received / invalid`。invalid のときは profile を返さない |
| 申請 | 既存の `POST /v1/requests`（`target_id`）。承認は既存の `PATCH /v1/requests/:id` |
| `GET /i/:token`（Web） | 未インストール時のHTML。表示名とアイコンだけ。`noindex`、キャッシュしない |
| `/.well-known/apple-app-site-association` | Universal Links 用 |

- アプリ側：Associated Domains（`applinks:`）を追加。`onOpenURL` でトークンを受けて受け取り画面を出す。
- 招待トークンの問い合わせはログイン（ゲスト認証）済みで行う。回数制限を付ける。

### 行きたいの共有

```sql
alter table profile_preferences add column share_want_to_go integer not null default 0;
```

| API | 内容 |
|---|---|
| `GET /v1/preferences` / `PUT` | 既存に `share_want_to_go` を追加 |
| `GET /v1/friends` | 各友達に `shares_want_to_go`（bool）を追加 |
| `GET /v1/want-to-go/common?friend_id=` | `{state, restaurants: [...]}`。state は `ok / self_off / partner_off / not_friend`。ok のときだけ、2人の `want_to_go` の共通部分を返す。相手の一覧全体は返さない |

- 友達関係とブロックは毎回D1の現状で確認する（既存の `connected()` / `blocked()` と同じ）。
- 件数だけ欲しいプロフィール用に `?count_only=1` を用意してもよい。

### 共有カード

サーバーの変更なし。画像は端末で作る。写真は自分のレビュー写真（既存の `/v1/photos` か端末内）だけを使う。

## 8. 見本で模擬している箇所

- 通信はすべて模擬（受け取りの確認中は1.2秒、共通の読み込みは1秒で次へ進む）
- QRコードは本物の形式で描いているが、中身は「MESHINOWA DEMO INVITE - NOT A REAL LINK」という文字（リンクではない）。実装時に招待URLから生成する
- 招待URL・WebページのURL・App Storeのリンク・地図のリンクは文字の見本
- iOSの共有シート、LINEの画面は見た目の見本
- 共通の地図は簡略化した絵
- カードの「あなたが撮った写真」は写真の位置を示す枠

## 9. 実装前に確認が必要なこと

- 招待URLのドメイン（Universal Links 用。Cloudflare の Workers に置くか）
- 地図のリンクを Apple マップと Google マップのどちらにするか
- 写真の保存に使う権限の文言（`NSPhotoLibraryAddUsageDescription`）
- 共有オフにしたとき、相手の画面の表示を「相手が共有していない」にすぐ切り替えるか（次の更新で反映でよいか）
